= FPSOT testing specification

Rules for how FPSOT projects test their software and their specifications.
It defines five test levels, from unit to end-to-end, and what each level may replace with a test double.
Functional tests start from Gherkin scenarios that teams write with domain experts, in English and in French.
It also covers contract tests, conformance suites, synthetic test data and the test jobs of continuous integration.
The rules are neutral on language and tools. Version 0.1 is a draft.

== Implement this spec

Read the normative text in `spec/en/` or `spec/fr/`.
Each requirement has an ID from `TST-001` to `TST-066`.

* Mark the level of each test, and run each level as a required check of the main branch (TST-001, TST-060).
* Keep each feature file in `features/en/` and `features/fr/`, with the same name and structure (TST-030 to TST-033, TST-036).
* Parse every feature file in the continuous integration and check the parity of the two versions (TST-034).
  In this repository, the `gherkin` job of `.github/workflows/ci.yml` runs `examples/test-features.sh`.
* Use synthetic data only, with reserved values and names in both languages (TST-050 to TST-057).

A business rule is plain code that an institution can override.
Its tests use the rule's own interface, so they check the default rule and any replacement (TST-005, TST-045).

== Adopt this spec

Read the guide in `docs/modules/en/pages/index.adoc` or `docs/modules/fr/pages/index.adoc`.
It writes a small feature in English and in French and checks it.
A request for proposals can ask that a product pass the conformance suite of a given FPSOT specification version.
A pass is not a certification (TST-047).
The comparison data in `jurisdictions/` shows how the guidance of Canada and Québec differs.

To check the example feature locally:

[source,shell]
----
python3 -m venv .venv
.venv/bin/pip install -r examples/requirements.txt
PYTHON=.venv/bin/python bash examples/test-features.sh
----

== Layout

[cols="1,3"]
|===
| Folder | Content

| `spec/`
| Normative text, in English and French. `book.adoc` joins the pages into one book, published as PDF with each release.

| `docs/`
| Guides, in the Antora folder layout.

| `examples/`
| The example feature in `features/en/` and `features/fr/`, the Gherkin check `check-features.py`, its tests `test-features.sh`, broken files in `invalid/` that the check must reject, and the pinned parser in `requirements.txt`.

| `skill/`
| The agent skill: a short summary that cites requirement IDs.

| `rules/`
| Machine-checkable rules. The Gherkin check is in `examples/`.

| `diagrams/`
| PlantUML sources and their rendered SVG files.

| `jurisdictions/`
| Comparison data: how each government handles the same topics.
|===
