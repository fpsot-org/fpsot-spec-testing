= Contract tests and conformance suites
include::_fpsot-terms.adoc[]

These rules cover two kinds of shared tests in {abbr-fpsot-first} projects.
A contract test checks an interface against its published contract.
A conformance suite checks that a component meets a specification, so that another component can take its place.

== Contract tests of an API

[[TST-040]]
*TST-040.* A provider of an {abbr-api-first} MUST test its server against the published description, under API-020 and API-021.
This is stricter than API-021, which only recommends such tests in continuous integration.
Each response in these tests MUST match the schema that the description gives for its operation and status code.
The tests SHOULD call each operation, and SHOULD produce each status code that the description lists.
Clients build against the published description, so a server that departs from it breaks them.
Only a test catches such a departure.

[[TST-041]]
*TST-041.* A provider MUST compare its description with the one of its last release, in continuous integration.
The check MUST fail on a change that breaks a client, as API-051 defines.
A change that comes with a new major version, under API-050, is the exception.
A tool then catches a breaking change before any client meets it.

[[TST-042]]
*TST-042.* A consumer and a provider MAY also use consumer-driven contracts.
In this method, the consumer's tests record what it needs from the provider, and the provider checks each record.
A consumer contract MUST NOT require anything that the published description does not allow.
When they differ, the published description wins.
Consumer contracts show which parts of an {abbr-api} each client uses.
The published description stays the contract for all clients.

[[TST-043]]
*TST-043.* A producer SHOULD test each event it sends against the published schema of its type, under API-102 and API-103.
A consumer of events then gets the data that the schema promises.

== Conformance suites

[[TST-044]]
*TST-044.* Each {abbr-fpsot} specification MAY ship a conformance suite.
A conformance suite MUST use only the public interfaces of a component, such as an {abbr-api} or files.
It MUST NOT require a given language, framework or runner in the component that it tests.
Any implementation, in any language, can then run the same suite.

[[TST-045]]
*TST-045.* A component that replaces another one MUST pass the same conformance suite as the component it replaces.
A component that replaces a business rule MUST pass the scenarios of that rule, except those it changes on purpose.
It MUST list the scenarios it changes, with their tags, and give a new scenario for each changed behavior.
Institutions can then swap a component or override a rule, and know what still holds.

[[TST-046]]
*TST-046.* Each release of a conformance suite MUST name the version of the specification that it tests.
Its major and minor numbers MUST match those of that version.
Each test MUST cite the requirement IDs that it checks.
A result can then say which rules a component meets, for which version.

[[TST-047]]
*TST-047.* A vendor or a project MUST NOT present a suite result as a certification, approval or endorsement by {abbr-fpsot}.
A vendor MAY state that a product passes a given suite release, with the date and the full results.
A suite checks the behaviors it covers, not the quality, the security or the support of a product.
Buyers must still assess these themselves.

[[TST-048]]
*TST-048.* A conformance suite SHOULD write its results in a form that a machine can read.
The results SHOULD give each requirement ID with its outcome: passed, failed or not applicable.
A buyer can then compare the results of several products, rule by rule.

== Comparison with GovStack

GovStack also checks products against its specifications, with tests of their {abbr-api} and a self-assessment.
Its link:https://govstack.global/software/how-is-compliance-measured/[compliance levels] grade a product by the share of requirements it meets.
A product that reaches a level can appear in the GovStack catalog.
{abbr-fpsot} grades nothing and lists no product.
A result names the suite release and the outcome of each requirement, under TST-046 to TST-048.
